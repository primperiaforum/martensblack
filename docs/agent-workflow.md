# Workflow правок сайта

Этот документ описывает, как коллегам и ИИ-агентам безопасно вносить изменения в сайт `apk-forum.ru`.

## Цель

Сделать сайт редактируемым через Git и ИИ-агентов без ручного хаоса в проде.

Правильная схема:

```text
запрос на правку -> ветка -> изменения -> проверка -> pull request -> review -> merge -> GitHub Pages
```

## Кто что делает

### Коллега

Формулирует задачу:

- какой блок изменить;
- какой текст был;
- какой текст должен стать;
- какие файлы/картинки приложены;
- есть ли deadline;
- нужна ли публикация сразу.

### ИИ-агент

Должен:

- прочитать `README.md` и `AGENTS.md`;
- найти нужный блок в коде;
- внести минимальную правку;
- не трогать запрещенные зоны без прямого разрешения;
- запустить проверки;
- подготовить commit или pull request.

### Владелец сайта

Проверяет diff, визуальный смысл правки и принимает решение о merge.

## Типовые задачи

### Правка текста

Пример запроса:

```text
В блоке "О выставке" заменить фразу:
"старый текст"
на:
"новый текст"
```

Агент меняет `index.html`, проверяет сайт и создает PR.

### Правка программы

В запросе нужно указать:

- день/сессию;
- время;
- тип сессии;
- название;
- преамбулу;
- ключевые темы;
- блок приглашенных спикеров.

Важно: в конце ключевых тем точки не ставятся.

### Замена изображения

В запросе нужно указать:

- куда вставить изображение;
- какой файл использовать;
- нужно ли конвертировать в `webp`;
- нужно ли удалить старый файл из репозитория.

Для сайта предпочтительно использовать `webp`.

### Правка стилей

В запросе нужно указать:

- блок;
- что визуально не нравится;
- желаемый результат;
- важные breakpoint, если проблема на телефоне/планшете.

Агент правит `source/style.css`, собирает `source/style.min.css` и обновляет cache-busting в `index.html`.

## Запрещенные зоны без отдельного разрешения

- Яндекс Метрика.
- Форма регистрации.
- Backend формы.
- Домен и DNS.
- Юридические документы.
- Массовое удаление файлов.

## Проверочный минимум

Перед завершением задачи:

```powershell
powershell -ExecutionPolicy Bypass -File tools\check-site.ps1
git diff --check
```

После публикации:

```powershell
powershell -ExecutionPolicy Bypass -File tools\check-site.ps1 -Remote
```

## Как писать хороший запрос

Плохо:

```text
Поправьте программу, там все не так.
```

Хорошо:

```text
В первой сессии заменить время на 12:00-13:30.
В подписи под временем написать 90 минут.
В теме "..." заменить слово "..." на "...".
Форму регистрации и backend не трогать.
```

## Как понять, что правка готова

Правка считается готовой, когда:

- изменения внесены в нужные файлы;
- проверки прошли;
- diff не содержит лишних файлов;
- pull request или commit имеет понятное описание;
- владелец сайта подтвердил публикацию.
