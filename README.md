# MARTENS_BLACK

Статический сайт форума `apk-forum.ru`: `11-й Всероссийский форум «Стратегические вызовы АПК: Готовая еда»`.

Сайт опубликован через GitHub Pages. Репозиторий является основным источником правды для кода, текстов, изображений и технических настроек.

## Быстрый старт

1. Открой `index.html` для структуры сайта и текстов.
2. Правь исходные стили в `source/style.css`, а не в `source/style.min.css`.
3. Правь исходный JS в `source/script.js`, а не в `source/script.min.js`.
4. После изменения CSS/JS пересобери минифицированные файлы и обнови cache-busting в `index.html`.
5. Перед коммитом запусти:

```powershell
powershell -ExecutionPolicy Bypass -File tools\check-site.ps1
```

## Основные файлы

- `index.html` - основной HTML сайта.
- `source/style.css` - исходные стили.
- `source/style.min.css` - минифицированные стили, подключенные на проде.
- `source/script.js` - исходный JS.
- `source/script.min.js` - минифицированный JS, подключенный на проде.
- `assets1/` - видео, изображения, логотипы, favicon.
- `assets1/webp/` - рабочие webp-фотографии для визуальных блоков.
- `assets1/age/` - webp-подложки для блока `Как это было`.
- `assets1/logo/` - логотипы.
- `docs/` - политика конфиденциальности, cookie и проектная документация.
- `backend/` - варианты backend-обработчиков формы. Не трогать без отдельной задачи.
- `tools/check-site.ps1` - локальная и remote-проверка путей сайта.
- `AGENTS.md` - правила для ИИ-агентов и коллег, которые вносят правки.

## Публикация

Боевой домен: `https://apk-forum.ru/`.

GitHub Pages берет сайт из ветки `main`. После push правки обычно появляются на сайте не мгновенно, а через короткую задержку.

## Автопроверки

В `.github/workflows/` есть два workflow:

- `site-check.yml` - проверяет локальные пути при push и pull request.
- `site-monitor.yml` - регулярно проверяет доступность production URL.

## Правила контента

- В конце ключевых тем программы точки не ставятся.
- Яндекс Метрику в `index.html` не менять без прямого запроса.
- Форму регистрации и backend не менять без прямого запроса.
- Для сайта использовать webp-изображения, если нет отдельной причины использовать другой формат.
- Не добавлять Tilda-экспорты и временные файлы в репозиторий.

## Рабочий процесс для правок

Для обычных текстовых и визуальных правок лучше использовать pull request:

1. Создать отдельную ветку.
2. Внести точечные изменения.
3. Запустить `tools/check-site.ps1`.
4. Описать, что изменилось.
5. Отдать pull request на проверку.

Ветка `main` защищена: правки должны проходить через pull request и проверку `site-check`.

Для подробного процесса смотри [docs/agent-workflow.md](docs/agent-workflow.md).
