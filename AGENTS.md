# AGENTS.md

Правила для ИИ-агентов и коллег, которые правят сайт `apk-forum.ru`.

## Роль агента

Агент помогает вносить правки в статический сайт форума. Он должен действовать как аккуратный технический редактор: сначала понять задачу, затем внести точечные изменения, проверить сайт и показать понятный diff.

## Главный принцип

Не ломать прод ради быстрой правки. Любые изменения должны быть минимальными, проверяемыми и обратимыми.

## Структура проекта

- `index.html` - HTML, структура блоков и большая часть текстов.
- `source/style.css` - исходный CSS.
- `source/style.min.css` - собранный CSS для прода.
- `source/script.js` - исходный JS.
- `source/script.min.js` - собранный JS для прода.
- `assets1/` - изображения, видео, favicon, логотипы.
- `docs/` - юридические документы и проектные инструкции.
- `backend/` - обработчики формы. Не трогать без явного запроса.
- `tools/check-site.ps1` - обязательная проверка путей.

## Что нельзя трогать без прямого запроса

- Код Яндекс Метрики в `index.html`.
- Форму регистрации и ее обработчики.
- `backend/`.
- `CNAME`, DNS, доменные настройки.
- Политику конфиденциальности и cookie-документы.
- Tilda-экспорт и локальные временные файлы.
- Чужие незакоммиченные изменения.

## Правила правок

- Для CSS менять `source/style.css`, затем пересобирать `source/style.min.css`.
- Для JS менять `source/script.js`, затем пересобирать `source/script.min.js`.
- После изменения min-файлов обновлять query version в `index.html`, например `?v=YYYYMMDD-N`.
- Для web-изображений использовать `webp`, если не сказано иначе.
- Не добавлять тяжелые исходники `jpg/png/mp4`, если сайт использует оптимизированную версию.
- Не делать крупный редизайн, если задача текстовая.
- Не менять стиль, палитру и сетку сайта без отдельного согласования.

## Правила программы

- В конце ключевых тем точки не ставятся.
- Время, формат сессии, название, преамбула, ключевые темы и приглашенные спикеры меняются только по предоставленной программе или явному тексту задачи.
- Если меняется количество сессий, нужно проверить табы, панели, якоря, JS-переключение и адаптив.
- Блок `Приглашенные спикеры:` сейчас используется вместо карточек конкретных спикеров.

## Проверки перед завершением

Минимум:

```powershell
powershell -ExecutionPolicy Bypass -File tools\check-site.ps1
git diff --check
```

Если был push в `main`, после публикации проверить remote:

```powershell
powershell -ExecutionPolicy Bypass -File tools\check-site.ps1 -Remote
```

## Git-процесс

Для коллег и внешних правок предпочтителен pull request:

1. Создать отдельную ветку от `main`.
2. Внести правку.
3. Запустить проверки.
4. Создать pull request с кратким описанием.
5. Ждать review владельца сайта.

Прямой push в `main` допустим только для владельца проекта или по явному разрешению.

## Формат ответа после работы

Коротко сообщить:

- что изменено;
- какие файлы затронуты;
- какие проверки прошли;
- был ли commit/push;
- есть ли остаточные риски.
